# Fortification cancellation and construction guidance — 18 October 2026

Status: source fix, not installed. Live baseline remains 0.7.13 / a4bc0ec46170b5b3c94356d2c7b2c03f90e7eab3.

## Report and evidence

The owner cannot cancel an untouched fortification blueprint and cannot find how to improve the fence. Read-only inspection confirmed an untouched stage-zero fortification upgrade between other sites with saved Progress/Hands. No production blueprint, material or player state was changed during diagnosis.

The API log confirms `JobProgress.ConstructionSite__synthesizedOrdinal` is read-only after save. Cancelling removes a site from an EF JSON-owned collection. The subsequent BuildState shelter save reuses the graph with shifted nested ordinals and fails, rolling back the cancellation transaction. Both DELETE blueprint and POST civic site-cancel reproduced HTTP 500 in new PostgreSQL API regression cases on the old source.

Separately, citizen SiteCard required a static catalog stage. FortificationUpgrade deliberately has no new-building catalog stages: its actual jobs are generated by the saved operation. This guard hid the entire working card from residents.

## Changes

- After cancellation has been saved, detach and reload the village within the same transaction before shelter assignment/DTO construction. Apply to both cancellation routes. Keep permissions, audit accounting and atomic commit; never bypass immutable-key checks.
- Render resident jobs and ruler queue stages from the server's actual site stages. Keep server job availability and material reservations authoritative.
- Show a Fence and gates card under Construction, after the active queue, as well as its existing Town location. Explain the three levels, technologies, shared queue, resident job path, separate repair, and deferred application during a raid.
- Show actual progress/job amounts for the existing reinforcement project. Before paid work, keep normal blueprint cancellation in the queue, disable it while pending, and show a failed request inside the menu with retry.
- After paid work, expose the existing confirmed dismantling flow: work stops and existing 25% material salvage rules apply. Do not offer free cancellation of invested materials. A dismantled upgrade does not remove the existing fence.
- Honour the saved hasWork flag, including progress outside the currently displayed stage; do not advertise the internal FortificationUpgrade as a future new building.

## Existing rules (unchanged)

Wooden fence strength x1 → log palisade x2 (Carpentry) → stone wall x3.5 (Carpentry + Mining). Costs scale with the actual perimeter. A ruler starts the communal project; residents deliver materials and work through Town → Help build. Maximum three communal sites; governor proposals still need approval. Repair buildings is separate work consuming wood and stone. An announced/pending raid blocks starting an upgrade; paid completed reinforcement waits for all waves to finish.
