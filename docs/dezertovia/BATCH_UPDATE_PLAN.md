## Новый порядок работы

1. Один раз прочитать актуальный код/решения, выбрать общую исходную версию,
   проверить состояние незавершённых PR и зафиксировать состав пакета. Для
   известных задач не запускать весь baseline-набор заново перед каждой правкой.
2. Подготовить зависимости и схему данных, затем последовательно реализовать
   ВСЕ строки пакета. Можно делать локальные коммиты для сохранности. Не открывать
   отдельный PR и не запускать CI/почти тысячу тестов после каждой кнопки.
3. Регрессионные тесты писать рядом с изменениями, когда они полезны, но запуск
   отложить до завершения согласованного пакета. Не создавать тесты ради простого
   удаления текста/кнопки и не дублировать реализацию проверками.
4. После окончания кода зафиксировать проверяемый commit и перейти к общей фазе
   проверки: формат/типизация/lint/сборка → содержательные новые сценарии → полный
   существующий набор затронутых систем → телефон/ПК и интеграционные сценарии.
5. Найденные ошибки собирать в один список и исправлять группами. После локального
   исправления запускать соответствующие упавшие/связанные тесты. Полный набор
   повторять только если изменения затронули общие контракты/данные/авторизацию/
   платежи или остаётся обоснованный риск. Не повторять778 тестов из-за опечатки
   в документации. Проверки должны относиться к итоговому коду, не старому SHA.
6. После локальной готовности опубликовать один итоговый PR игры и при изменении
   бота один связанный PR бота. CI нужен на финальном коде, не на каждом промежуточном
   шаге. Не менять/отключать существующие обязательные CI-проверки ради экономии;
   сократить лишние промежуточные публикации и отменять только устаревшие runs.
7. Дать один итоговый отчёт: реализованное, реальные результаты проверок,
   оставшиеся ограничения и точный состав выпуска. Во время работы — короткие
   сообщения о результате блоков, без требования отдельного «продолжай» на каждый.

Чтение кода и проектирование остаются до/во время правок. Системные/синтаксические
ошибки, замеченные редактором, можно исправлять сразу; это не повод запускать
полную батарею. Не переносить проверку прав/сохранности на момент ПОСЛЕ применения
изменений к live: рабочие данные и сервер до отдельного выпуска не меняются.

- Реальный обмен ДЗК↔свечи, новые налоговые ставки и автономные списания ИИ.
  Экономика тестовая, текущие реальные тарифы лечения — отдельный готовый контракт.
- Повторные массовые разбаны, восстановление игроков, смену AI-ключей/моделей,
  обновление всех зависимостей и произвольный reset. Это не игровые правки пакета.
- Новый замок/территориальную экономику автоматически: важный отдельный план,
  не расширять этим всю миграцию мира без явного включения владельцем.

## Финальная фаза проверки — один общий заход

**Сборка и проверки кода.** TypeScript/lint/production build; .NET build; Python
синтаксис/целевые правила; миграции на изолированной копии тестовых данных.
Далее необходимые Domain/API/бот-тесты. Если бот не менялся — не гонять весь его
набор лишь из-за изменения CSS игры; если менялись деньги/медицинский bridge/
общий Brain — полный затронутый набор обязателен.

**Сквозные проверки по результату, не по каждой строке:**

- закрытый мост → запрет клика/API/очереди → все стадии → приёмка → переход;
- группа строителей с разными навыками → достижимый надзор → честные XP/слава;
- миграция полного склада → улучшение → разборка с проверкой груза/вместимости;
- заселение при дефиците → улучшение → переселение → снос занятого жилья;
- брак → связь по ID → совместное жильё → смена ника → развод/offline sync;
- дуэль → ранение → пауза → бесплатное/платное лечение → единственный исход →
  выписка; retry/перезапуск не меняют деньги/срок/награду второй раз;
- истощение → медленная работа при нормальной ходьбе → восстановление;
- пустой чат с работающими игроками → тишина; активный чат → редкая уместная
  реплика; отсутствие географии/повторов и корректность серьёзных ответов;
- телефон320px/длинный экран и desktop16:9: карточки, снос, склад, госпиталь,
  кириллица, day/night, тёмная тема, чат всех режимов, reconnect/SignalR.

Регрессии: авторизация/права, online/offline, сохранность идентичности/прокачки,
очередь, фоновые workers, восстановление после restart, idempotency платежей/
наград. Тесты на фиктивном Telegram/ИИ и временных БД; никаких тестовых сообщений
в настоящий чат, настоящих списаний или копирования приватных данных в git.
Полный финальный прогон не обещает отсутствие багов: сохранять rollback и
проверять реально установленные источники/health после разрешённого выпуска.

## Граница завершения и выпуска

«Готово» — все включённые строки реализованы либо конкретное непреодолённое
ограничение явно описано, финальные проверки относятся к итоговому commit,
миграции и зависимости понятны, PR/журнал/патчноут актуальны. Не выдавать
собранный код/старые результаты/черновой PR за выпущенную игру.

По умолчанию поручение выполнить план = код и PR, без deployment. Выкладка,
реальные балансы/перенос live и разрушительные операции требуют отдельного
явного разрешения, если его нет в самом следующем запросе. После такого
разрешения не спрашивать повторно на каждый технический шаг.

Готовая формулировка следующего поручения:

> Выполни весь пакет из BATCH_UPDATE_PLAN.md одним заходом. Сначала закончи все
> правки, потом проведи общую проверку и тесты. Исправь найденные ошибки, сохрани
> итог в GitHub. На сервер пока не выкладывай.
