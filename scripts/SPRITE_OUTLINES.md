# Обводка спрайтов без ИИ

Python 3.10+ и Pillow. Скрипт работает локально, без API и расхода лимитов генерации.

```sh
python -m pip install Pillow
python scripts/outline_sprites.py art/night-buildings --output art/outlined-buildings --pattern "building-*.png" --width 2 --color "#2b1d2b"
```

Или одна картинка:

```sh
python scripts/outline_sprites.py art/night-buildings/building-hut-day.png --output art/outlined-preview --width 2
```

- PNG должен иметь прозрачный фон. Контур внешний; прозрачные отверстия внутри не обводятся.
- `--width` — пиксели исходного изображения, не пиксели экрана. Общий профиль задаёт1 игровой пиксель; при2 пикселях исходника на игровой пиксель получается обводка2px. У больших ночных исходников может понадобиться большая толщина.
- `--color` — цвет контура; тёмный коричнево-фиолетовый близок к остальной графике.
- `--threshold` — порог прозрачности силуэта. По умолчанию192: слабое свечение не создаёт контур, но яркое свечение всё ещё может попасть в силуэт.
- Для точной обводки ночного здания используйте `--mask-dir`: прозрачные PNG с непрозрачным силуэтом здания, такими же именами, размерами и расположением. У наших оригинальных day/night PNG разные размеры и геометрия: нельзя просто подставить дневные файлы как маски.
- Исходники сохраняются. `--overwrite` заменяет только результаты предыдущего запуска в отдельной папке.
- Размер холста по умолчанию сохраняется. Если объект касается края, контур там обрежется; `--padding 2` добавит поля, но тогда при интеграции нужно скорректировать привязку/anchor.
- Обводите отдельные спрайты **до** упаковки в атлас. Не запускайте скрипт на общей карте, обзорной картинке или готовом смешанном атласе.

Результаты не подключаются автоматически к игре. Сначала сравнить день/ночь, затем упаковать в соответствующий атлас с прежними именами и привязками. Версия игры и сервер этим инструментом не меняются.

Единый профиль: `art/style/building-outline.json`. Рендерер `BuildingLighting` использует его автоматически для всех26 подключённых дневных/ночных зданий. Контур строится в мировых координатах, поэтому размеры PNG и площадь участка не меняют толщину. Цвет и порог силуэта общие; свечение рисуется отдельно. Между дневным и ночным силуэтами контур меняется плавно.

Для PNG скрипт читает тот же профиль. `--pixels-per-world` задаёт масштаб исходника; исходные day/night изображения имеют разный масштаб, поэтому применение одинакового `--width 2` к ним НЕ гарантирует одинаковый вид в игре. Использовать либо мировой контур рендерера, либо подготовленные PNG с правильным масштабом, не оба сразу — иначе контур удвоится. CLI-переопределения предназначены для отдельных экспериментов, штатный единый стиль меняется только в JSON.

Проверено локально: production build/lint;6 GPU-проверок (ПК/телефон,26 зданий,
одинаковая непрозрачная краска контура, непрозрачность перехода, emission).
Скрипт обработал26 дневных и26 ночных файлов в временные папки; синтетическая
проверка подтверждает точную толщину, сохранение непрозрачных деталей/внутренних
отверстий/размеров. Новые PNG в runtime atlas не подключались. Сервер не обновлялся.
