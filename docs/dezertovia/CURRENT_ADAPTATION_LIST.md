# Что исправляем в обновлённой игре автора для нашей Дезертовии

План от 14.10.2026. Проверена отдельная копия автора на коммите
`e23bc943bac17e55d4d5a0b0805d07d53de02108`. Игровой код в нашей ветке
ещё основан на 492cf291; обновление автора не слито и не выложено.

Этот список уточняет прежнюю матрицу после большого обновления. Наша цель —
сохранить существующую инженерную основу и её стиль, меняя несовместимые
правила и дополняя отсутствующие функции. Нового художественного блока нет.

## Уже есть в новой основе — сохраняем

.NET/Domain/Api/EF/PostgreSQL, React/PixiJS/Vite, SignalR, аккаунты и Telegram
Login Widget, редактор внешности, стадийная стройка, склады/груз, навыки,
технологии, локализация, карта/мини-карта, присутствие, чат и назначаемые Governors.
У автора также есть набеги и отдельная realtime dungeon-карта. Это наличие
кода, а не одобрение боевого режима для нас и не выполненная проверка на нашем сервере.

## Порядок первого адаптационного захода

1. Отдельно принять и проверить обновление автора, сохранить наш docs слой,
   проверить diff CI/deployment/скриптов и baseline tests. Сейчас это ещё не сделано.
2. Telegram + одно царство + права царя/помощников; запрет неподходящих боевых сценариев.
3. Роль/очередь/энергия/приток/участки — один полный медленный игровой цикл.
4. Общий/внешний запас, общие и личные стройки, производства и изделия.
5. ДЗК, рынок, exchange, статистика и отчёт — один проверяемый экономический пакет.
6. Дополнив existing chat батюшкой, проверить телефон/PC/reconnect/уведомления.
7. Изолированный тест на нашей инфраструктуре; перенос либо новый тестовый мир
   только по отдельному решению, затем конкретный reviewable выпуск.

Не переносить все системы сразу одним большим patch. Новые параметры — предложения,
не уже изменённые значения. Каждая очередь/денежная операция проходит tests и
сохраняет единственного authoritative writer в .NET.

## Что переносим из старой версии как идеи и сценарии, а не файлы целиком

Профессии2ч, queue1+1, ограничения склада/участка, funding/заявки/помощники,
медленная совместная работа, журнал/рынок/тестовая экономика, бот-контракты.
Не копируем SQLite schemas, Python engine, старый HTML/Canvas UI, сессии/ключи
или реальные player data поверх EF/React/PixiJS.

## Какие решения ещё выбрать

- Длинные времена автора 3/5 минут либо другой утверждённый бюджет; skill
  reductions и morale/streak bonuses проверяются вместе с итоговой выдачей.
- Энергетический бюджет, восстановление и старые приобретённые бонусы: сравнивать
  число полезных действий/время, а не буквально 14/100 и 1/36 разных шкал.
- Бой в подземелье в будущем: у автора уже realtime и потери прочности/раны,
  зритель предлагал text и сохранение добычи. Нельзя объявить их одним механизмом.
- Старое состояние текущего мира импортировать или новый test realm; не сбрасывать
  старую игру из прежнего разрешения на другой тест.
- Какие готовые дополнительные открытия/занятия автора включать первыми. Они
  полезны, пока не обходят принятую профессию/расходы/сложность развития.

Дальние идеи (замок/баня/таверна/качество/износ/тиры/данжи/больница) сохраняются
в VIEWER_BACKLOG. Наличие теперь готовой Tavern/Raids/Dungeon не делает все прежние
идеи реализованными для нас: сопоставить фактическое поведение и правила.
