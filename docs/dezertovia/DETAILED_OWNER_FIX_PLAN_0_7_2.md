# Единый подробный план исправлений после 0.7.2 · D-080

16.10.2026. Статус: PLAN, не реализация и не новый выпуск.
Основание: OWNER_FEEDBACK_0_7_2_REVIEW.md — 12 требований на трёх скриншотах,
4 последующих уточнения и 16 групп прежних жалоб для контроля регрессий.
Этот документ задаёт порядок реализации всего объёма, не заменяет исходную сверку.
Последний подтверждённый runtime: 0.7.2 / 04c395052a106562b8e00b6c73a8a5b119b1aea5.
Перед будущим кодом сверить новые main/коллегу/фактический runtime, не затирать изменения.

## 1. Результат и границы

- На карте остаётся компактная навигация и личные показатели. Нет постоянных
  кнопок стройки/голосования, дублирующего выхода, обязательной карточки врага.
- Клик по врагу — выбор цели, достижимый подход и повтор ударов. Личные боевые
  действия работают на сервере; их доступность объясняется в интерфейсе.
- Игроки и враги движутся одинаково плавно; сервер остаётся источником позиции/урона.
- Снос жилья имеет понятные условия и одинаковые причины в игре и Telegram.
- Недострои и все игровые типы зданий имеют последствия вражеского разрушения.
- Центральный замок, поражение и назначение монастыря входят в общий объём;
  это пока проектирование, их нельзя отметить готовыми после UI-правок.
- Не сбрасывать навыки/славу/предметы/вложения/лечение и не облегчать стройку.
  Новые числовые параметры ниже — рекомендации для реализации/проверки, не текущие правила.

## 2. Порядок работы

1. Зафиксировать актуальную основу, DTO/серверные состояния и правила миграции.
2. Реализовать серверные команды боя и понятный снос/расселение.
3. Реализовать единый lifecycle повреждения/руин/восстановления и последствий.
4. На нём реализовать нападения на недострои, замок/поражение и монастырь.
5. Подключить клиент: клик, панель боя, сглаживание, HUD/меню, короткие ссылки.
6. Согласовать Telegram-карточки и причины; обновить документацию/патчноуты.
7. После всего выбранного кода — общий поиск ошибок, целевые тесты, итоговый CI.
   Если обнаружены ошибки, исправить и повторить затронутые проверки; новый код
   требует проверки своего точного source. Не запускать полный набор после каждой CSS-правки.

Это зависимости внутри общей задачи, не исключение сложных пунктов и не серия
обязательных отдельных запросов владельцу. Поручение сейчас — составить план.

- Подробности врага/позиционные команды доступны отдельно, если нужны, не при каждом тапе.

Готовность: живой враг/отступающий враг/двойной клик/смена цели/закрытие меню/
смерть цели/reconnect; одна сущность на аккаунт, чужим бойцом управлять нельзя.

## 5. Рабочие боевые действия · COMBAT-07

Точки: RaidFighter, GameService.Battles.cs, RaidSimulation, API/DTO, личная панель.

Панель в одну строку над нижней навигацией, только при личном активном бое:
«Отступить» и «Лечение». У предупреждения/зрителя/после окончания её нет.
Новая «Защита» исключена: hold не снижает урон; не выдавать его за блокирование.

### Отступить

- Сервер сохраняет состояние Retreating, достижимую точку и последующее Withdrawn.
- Прекратить преследование/удары, двигаться к точке отхода, оставаясь уязвимым.
  Недостижимая точка не вызывает телепорт: искать допустимую альтернативу/дать отказ.
- После отхода Guard не должен вернуть игрока автоматически следующим тиком.
  Повторное вступление только явно; не восстанавливать HP/стрелы, не создавать дубль.
- Смерть/ранение/конец волны отменяют переход согласованно; состояние переживает рестарт.

### Лечение

- Рекомендация: 1 лекарство восстанавливает 20% максимальных боевых HP,
  не выше максимума; откат 60 секунд, без снятия ранений/дуэльных ограничений/обморока.
- Использовать допустимый личный/общий запас по существующим правам. Царю
  не создавать выдуманный личный инвентарь: доступный разрешённый общий запас.
- Нет лекарства → тёмная настоящая disabled-кнопка, «Нет лекарства» без hover.
  Полный HP/откат также блокируют с причиной. При поступлении запаса обновить без reload.
- Сервер в одной сериализованной операции повторно проверяет бой/роль/HP/запас,
  списывает предмет, меняет HP и откат. Идемпотентный request ID защищает повтор.
  Не использовать обычный me/heal как будто он уже лечит RaidFighter.Health.
- Старые сохранения получают безопасные значения новых полей; никакого нового
  боевого персонажа/восстановления HP через повторный вход или очередь волн.

Готовность: гонка за последнее лекарство, повтор после timeout, лечение/ранение
на одном тике, царь/житель, выход/возвращение, рестарт и окончание волны.

снос недостроя, Telegram и игра дают одну причину; реальные решения не принимать тестом.

## 8. Недострои и все типы зданий под ударом · COMBAT-06

Точки: RaidSimulation.Targets, CombatRules, ConstructionSite, Structure,
StorageBuilding, CycleEngine/settlement, навигация, EF/DTO/renderer.

- Общая серверная цель: стабильный ID, plot, тип/владелец, footprint, состояние,
  допустимость удара и целостность. Включить общие/личные Sites, готовые дома,
  склады, производство, больницу, замок и остальные реальные типы каталога.
  Таблица покрытия должна перечислять каждый тип, исключения только явные.
- Не считать декорации серверными зданиями. Мосты/ворота/ограды — отдельная
  геометрия/переходы: определить их разрушение без несуществующих проходов.
- Жизненный цикл: целое → повреждённое → руины → восстановление → целое.
  Рекомендация: использовать прежнюю шкалу Damage 0–100, при 100 переход в
  руины одной доменной операцией, а не удаление записи/связанных данных.
- Недострой при обрушении прекращает новые задания и освобождает резервы.
  Уже оплаченный/совершающийся цикл завершается или прерывается по явному правилу,
  один раз учитывая переносимые материалы; не начислять вклад за несуществующую работу.
- Дом: при вынужденном разрушении теряет жилые места, жильцы сохраняются,
  получают состояние без крова/нужду переселения. Удар врага не блокируется
  правилом добровольного сноса «сначала найдите кровати». Не дарить бесплатные места.
- Склад: остатки привязаны к руинам/доступной добыче по ограниченным правилам;
  запрет бесконтрольной потери/дублирования при одновременном производстве/вывозе.
- Производство/технологии: работа в нерабочем здании недоступна, уже изученные
  знания не стираются; оплаченные циклы и вещи требуют сохранённого settlement.
- Больница: больные не исчезают и не лечатся бесплатно; резервный полевой лазарет
  сохраняет их сроки/ограничения. Перенос на новую больницу не удваивает пациентов.
- Восстановление — отдельные ресурсы/труд с учётом типа/уровня и сохранённых
  вложений, не бесплатная кнопка и не повторное полное начисление славы/материалов.
  Стоимость рассчитать по текущему каталогу, не назначать универсальный процент вслепую.
- Сохранить ограничение разорения события. Сейчас PlunderDamageLimit=180;
  простое снятие этого cap недопустимо. Сначала нормировать цену повреждения
  целей/уровней и проверить тяжёлый, но не тотальный ущерб. Возможность разрушить
  любой тип не означает обязанность снести всю деревню одной волной.

Готовность: повтор тика/рестарт/двойной удар/разрушение при завершении стройки,
производстве/лечении/сносе, личное и общее имущество, сохранность всех связанных сущностей.

## 9. Замок и поражение · CASTLE-02

- Для нового мира рекомендация: центральный слабый замок 1 уровня с последующим
  трудным улучшением. Не менять численность/силу врагов только ради его появления.
  Проверить реальный footprint, стартовые объекты, проходы, чтобы место было достижимо.
- Для существующей деревни сначала read-only карта центра/текущего замка/участков.
  Не двигать и не сносить дома/замок миграцией. Подготовить конкретное свободное
  размещение/поэтапный перенос с сохранением затрат; при конфликте решение владельца
  необходимо по реальной схеме, не по абстрактному вопросу до её подготовки.
- Различать проигрыш отдельного рейда (уже есть RaidOutcome.Lost) и поражение
  поселения из-за потери замка: новый устойчивый статус, причина/время/event ID.
- Рекомендация: потеря замка → «Поселение разорено», обычный раунд обороны окончен,
  оставшиеся волны этого события остановлены без наград за отменённых врагов;
  доступен тяжёлый путь восстановления. Не удалять мир/аккаунты/персонажей,
  не сбрасывать навыки и не запускать бесконечные атаки по уже проигравшим.
- Зафиксировать разрешённые дела в этом состоянии: лечение, спасение, разбор
  завалов и восстановление; новые наступления/царские расширения ограничены явно.
- Поражение обрабатывается один раз, одинаково для всех клиентов и после рестарта.
  Замок не неуязвим для нежити из-за запрета его ручного сноса.

Готовность: поражение/отмена атаки/одновременный последний удар, восстановление,
старый мир без центрального замка, никаких новых правил до корректной миграции.

## 12. Ранние жалобы и директор не теряются

Использовать 16 групп регрессий в исходной сверке. Обязательны чат/подписи,
свои характеристики и супруг, ники, пациенты/переноска, дверь/зависшие резервы/
вклад и повторный settlement, границы личных участков, берег/ворота, остановка
нежити, заявки/очередь/улучшения, питание/переутомление, автор/версия отзыва.
Старый release record доказывает прежний выпуск, не новый сценарий на текущем source.

Директор — один Всевышний, предложения по экономике/налогам/врагам, а не
советы игрокам как развивать село. Существующие анализ/Propose, настройка взвара
и энергетик не переписываются. Новые налоговые/экономические исполнители и
сводка причин молчания остаются отдельными открытыми задачами, не объявлять их
выполненными данным UI/осадным пакетом. Сверяться с ALMIGHTY_IMPLEMENTATION_PLAN.md
и CIVIC_REQUEST_CAPACITY.md; при расширении дать server-issued bounded options,
права/лимиты/журнал/одобрение владельца, без прямого SQL/произвольных сумм от модели.

## 13. Финальная проверка и выпуск

- Сначала весь выбранный код; затем meaningful Domain/API/browser проверки
  поведения, общий lint/TypeScript/build и обязательный CI точного source.
- Domain: позиции/цели/урон, retreat/heal/idempotency, койки, руины/settlement,
  очереди/отмена, поражение/восстановление, повтор после рестарта.
- API: роли/свой-чужой/царский герой, гонки запасов/мест, HTTP reasons/status,
  повтор callback/timeout, миграция старых сохранений.
- Browser: телефон/ПК и темы, реальный tap/drag, скрытые окна, доступность клавиатурой,
  HUD/числа/чат, disabled medicine, гладкость/задержанные снимки, старые/новые URL.
- Единый локальный сценарий: предупреждение → вход врагов → клик → бой → лечение/
  отход → удар по недострою/складу/больнице → ранения/руины → конец → восстановление.
  Отдельно ветка потери замка и ветка добровольного сноса с переселением.
- Миграция на копии: профили/Telegram bindings/XP/характеристики/слава/инвентарь/
  деньги/жильё/стройки/ранения/свечи сохранены; данные разрушений меняются только
  при настоящем событии, не при применении схемы. Старый движок автоматически не ставить.
- Локальные данные и фальшивые HTTP для тестов; никаких настоящих сообщений,
  платежей, модельных проб или волн игрокам ради проверки.
- Следующий исправляющий номер — кандидат 0.7.3, не 0.8/1.0; не повышать за план.
  Существенный новый этап осады имеет отдельное содержательное решение о версии,
  количество коммитов не повод скачка. Весь план не считается готовым, пока
  остались незавершённые пункты; частичный выпуск описывать как частичный.
- Установка этим запросом не выполняется. При разрешённом будущем выпуске:
  актуальные AGENTS/оператор/candidate, точные CI/pins и baseline, backups,
  install и отдельный независимый check с preservation receipt. Публичный game
  и приватные ops сохранять согласованными, private main/старые triggers не трогать.
