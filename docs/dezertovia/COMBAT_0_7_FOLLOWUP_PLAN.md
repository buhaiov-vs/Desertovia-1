# Исправления боёвки после 0.7 · 16.10.2026

**Статус: PLAN / TODO.** Владелец прислал скриншоты нападения (26 врагов,
северный подход), карточки отступающего упыря и четыре замечания. Сейчас
разрешено сохранить подробный план, без реализации, выкладки или остановки
текущего реального нападения. Действующий выпуск 0.7 — `0540a2a`.

## COMBAT-02A / P1 — стык забора с рекой

**Жалоба:** нежить обошла забор у воды. Сначала установить фактическую геометрию
данной карты: видимые колья, сохранённые Fortifications, клетки суши/воды,
берег реки, ворота и проломы. Не объявлять всякий обход ошибкой маршрутизации:
по открытой сухой щели враг действительно может пройти.

**Подтверждённый риск кода:** `Fortifications.Ensure` создаёт северную/южную
стороны на y=-1/26 только до x=27; восточной стороны нет. `RaidNavigation.Dry`
проверяет фактическую карту и `Wilderness.RiverWestBank`. Если берег восточнее
конца стены, между ними может оставаться сухой проход. Точный маршрут со
скриншота ещё не воспроизведён; это причина для проверки, не готовый диагноз.

**Порядок исправления:**
1. Сверить клетки визуального забора и серверных препятствий на реальной карте.
2. Если открытая полоса суши возникла из-за прежней фиксированной длины забора,
   согласовать и исправить реальное примыкание ограды к непроходимому берегу;
   отображение и коллизия должны совпадать. Не добавлять невидимую стену.
3. Проверить запрет движения по воде/непроходимому берегу и срезания углов.
   Открытые ворота, настоящий пролом и намеренно незакрытая сухая тропа остаются
   рабочими путями. При отсутствии прохода нежить ломает забор по правилам.
4. Старые повреждения, положения ворот и улучшения ограды сохранять; не
   пересоздавать весь массив Fortifications с обнулением Damage/Open.
5. Учесть север/юг, разные изгибы реки и расширение царства: рост территории
   сам по себе не переносит старую построенную ограду.

**Приёмка:** для закрытой и целой ограды с корректным стыком нет прохода
в обход по запрещённым клеткам; через реальные ворота/пролом пройти можно.
Проверять серверный маршрут и отображение одного и того же участка.
Файлы: `Combat/Fortification.cs`, `Combat/RaidNavigation.cs`, AuthoredTerrain,
Wilderness, `web/src/game/worldMap.ts`, VillageWorld и enemies.

## COMBAT-02B / P1 — царь может лично атаковать

**Подтверждено:** `BattleControls` показывает атаки только если есть Citizen,
охранная задача и активный RaidFighter. `SetBattleOrderAsync` требует
`RequireCitizenAsync` и `RaidRules.GuardTask`. У царского аватара отдельно
хранятся `Village.TsarSpot/TsarTrip`; одно право владельца не создаёт бойца.
Поэтому у царя может открываться только информационная карточка без атаки.

**Сделать:**
1. Определить единственную серверную боевую сущность владельца: использовать
   его существующего персонажа, если он есть; для отдельного царского аватара
   предусмотреть собственное устойчивое боевое состояние. Не создавать чужого
   персонажа/второго царя и не выдавать бессмертие административной ролью.
2. В карточке врага дать царю понятное действие «Вступить в бой»/«Атаковать»,
   затем выбор цели, ближайшего противника и режимов позиции/перехвата.
   Если сначала нужна подготовка — показать причину и действие, не скрывать
   все кнопки молча. Право задавать бойцу команду проверяет сервер.
3. Дистанция, путь, здоровье, оружие/броня, откат ударов, ранение и восстановление
   работают по общим правилам. Нажатие задаёт цель; не наносит удалённый урон
   с любого места карты. Царь может атаковать живого отступающего врага, пока
   тот не ушёл с карты и бой не завершён.
4. Текущее дело не отменять молча; переход к обороне согласовать с очередью,
   уже оплаченными входами/временем и возвратом экипировки.
5. Сохранить возможность обычным жителям участвовать в обороне. Предложение
   из предыдущего обсуждения — самооборона всем доступным жителям, дозор
   для организованной защиты/перехвата — отдельное проектное решение,
   пока не считать эту более широкую механику уже утверждённой или реализованной.
   Для ясности рассмотреть «Встать на защиту» и «Защитников: N» вместо старого
   обозначения; не удалять дозор, пока от него зависит серверная боёвка.

**Приёмка:** царь без Citizen видит понятный путь участия; его собственный боец
атакует допустимую цель. Дозорный, обычный житель, раненый, посетитель и чужой
аккаунт получают правильные действия/отказы; чужими бойцами управлять нельзя.
Файлы: `GameService.Battles.cs`, RaidSimulation/RaidBattle, Village,
`BattleControls.tsx`, `RaidBanner.tsx`, GamePage и DTO/API.

и не теряет остальное состояние интерфейса.

## COMBAT-02D / P1 — «Усыпить нежить» останавливает идущую атаку

**Причина подтверждена:** `CancelUndeadAsync` выбрасывает
`raid.alreadyFighting` для начавшегося боя engine>=2. Сейчас разрешена только
отмена ожидающей волны. Это не соответствует требованию владельца.

**Требуемая семантика:** команда царя останавливает текущую атаку нежити и
все ожидающие/отложенные волны этого события. После подтверждённого сервером
усыпления нежить перестаёт двигаться, атаковать игроков, ломать здания и
воровать; оставшиеся единицы исчезают с карты согласованно с состоянием сервера.
Существующие ночные нападения зверей не отменяются этой кнопкой.

**Порядок реализации:**
1. Добавить явное терминальное состояние отменённого события, согласовать
   Raid.Outcome/ResolvedAt и RaidBattle.Phase/FinishedAt. Сейчас RaidOutcome
   имеет только Pending/Repelled/Lost; не маскировать отмену под победу и не
   удалять историю уже состоявшегося боя.
2. В одной сериализованной транзакции завершить активный бой и пометить
   ожидающие волны события отменёнными. Гонку с Tick и повтор команды сделать
   безопасными: после commit не может пройти ещё один удар или старт волны.
3. Сохранить уже нанесённый урон, ранения, реальные смерти врагов и фактически
   состоявшиеся операции. Не откатывать время, лечение, предметы и стройки.
   Не выдавать фиктивный лут/славу за оставшихся усыплённых врагов и не начислять
   награды повторно; для фактического участия использовать общие правила.
4. Освободить только боевые ссылки/цели данного события; вернуть бойцов в
   согласованный режим без сброса чужой работы/лечения/экипировки.
5. Через существующий канал обновлений убрать активный баннер и карточки
   исчезнувших врагов у всех клиентов; журнал показывает «Нежить усыплена царём».
   При ошибке интерфейс показывает отказ, а не делает вид успешной остановки.
6. Сохранить право операции только за владельцем царства; повтор после успеха
   возвращает понятное уже завершённое состояние. Перезапуск сервера не
   возобновляет отменённый бой или оставшиеся волны.

**Приёмка:** до прихода, на подходе, во время боя, при отступлении, между
волнами; двойное нажатие, одновременный Tick, повтор после reconnect/restart,
запрос обычного игрока. Нет новых ударов/ущерба после остановки, фальшивых
побед/наград и затрагивания независимого другого события.
Файлы: `GameService.CancelUndeadAsync`, `Combat/RaidRules.cs`, `Raid.cs`,
RaidSimulation, очередь волн, DTO/переводы, `UndeadPanel`, renderer.

## Порядок и проверки общего пакета

Рекомендуемый порядок: остановка нападения → участие царя → стык ограды/берега
→ карточка/крестик и тексты. Сначала закончить согласованные правки, затем
провести целевые domain/API проверки и один общий браузерный сценарий:
предупреждение → подход → забор/ворота → царь вступает и выбирает цель →
закрытие карточки → усыпление → отсутствие оставшихся волн/ударов.
Не генерировать реальные тестовые нападения на production. Игроки/прогресс/
лечение/имущество сохраняются. План не является разрешением на немедленную
выкладку и не сообщает об уже выполненных исправлениях.
